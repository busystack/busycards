# Native and rendered acceptance

BusyCards Linux debug/release and an independently copied BusyMax reference release compile. Compilation is not native execution or rendered parity. BusyMax originals were not built/tested/launched.

The reference copy is validation/references/busymax, without donor .git, generated directories, app profiles or credential stores. Its resolved package cache is validation/reference-pub-cache; the copy alone generated its own .dart_tool/build. Matching public native SQLite artifacts were independently copied and hash verified. The copy includes only the required source/resources/native registration-reader implementation, not owner registrations. Donor revisions and initial states are in read-only-verification.md.

Isolated launch profiles are validation/profiles/native-acceptance/{busycards,busymax-reference}, with separate XDG data/config/cache/runtime (0700), unset owner DISPLAY/Wayland/DBus addresses, no connection to installed apps and no personal credential use. Both attempted `dbus-run-session -- xvfb-run -a <release-binary>` with GDK_BACKEND=x11. Both exited 127 because DBus could not bind a Unix socket (Operation not permitted). No application frame was rendered or captured. native-acceptance.json and native-*-isolated-x11.log record the attempts. GTK native CTest likewise could not start DBus. Three compiled native tests are registered; source/native assertions were not executed. The helper cache-fixture sandbox cannot establish mount namespaces (bubblewrap Operation not permitted).

No independent Wayland compositor (weston/cage/sway) is available, and the owner’s running session was not accessed. Wayland is unverified. The required `flutter test` runner cannot bind its loopback HTTP socket: 14 test files fail during loading, with zero assertions executed by that command.

A separate, explicitly supplemental runner (`tool/headless_contract.py`) compiles the original BusyCards test mains with the pinned Flutter frontend and runs the actual `flutter_tester` engine with assertions enabled and no VM-service/test-driver socket. It registers their unchanged test bodies through the resolved test_api backend. It executed 165 passing cases across all 14 files; the Google authorization file has 14 passing selected cases and 18 explicitly excluded browser/socket cases. No other cases are excluded. `validation/headless-summary.json` contains the per-file counts, logs and exact excluded names. These are actual widget/application/platform-channel fixture tests; no production provider or persistence path is replaced by a demonstration implementation. Native service calls are mocked only in widget/platform tests, as in the donor tests. They do not make the required standard runner pass and establish neither GTK release rendering nor live providers.

The runtime and five UI workflow suites exercise the real encrypted adapter and app use cases. They found and fixed an in-flight future cleanup self-wait, missing route Scaffold ownership, cross-sliver measurement-key reuse and duplicated search debounce. Google credential coalescing now has a regression; the GTK preload regression retains observed Riverpod 3 subscriptions. All these supplemental suites pass. Exact BusyMax appearance still requires the actual native/release comparison below.
