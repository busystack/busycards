## Rebuilding the sibling layout

Extract busycards-0.1.0-source.tar.gz into an empty directory. It contains busystack_dav/, busystack_graph/, busystack_contacts/ and busycards/ as siblings. No root workspace is added. Connected hosts use `python3 tool/verify.py --flutter /path/to/flutter/bin/flutter` from busycards. Offline hosts first extract busycards-0.1.0-offline-inputs.tar.gz elsewhere, run `python3 tool/prepare_offline.py /path/to/inputs`, then set PUB_CACHE and BUSYCARDS_MAVEN_REPOSITORY to this extraction’s validation directories and pass --offline. prepare_offline verifies every file before copying it; it creates independent files, not links to the original build’s caches. Tests/builds never require an original app checkout or installed app.

`python3 tool/package.py` produces local release/source archives and manifest/SHA256SUMS. Tar entries are sorted; uid/gid/names, file/directory modes and timestamps are normalized; executable files retain execute permission; gzip timestamps and header names are fixed. SOURCE_DATE_EPOCH defaults to 1790899200. Java jar outputTimestamp is fixed. Archive reproducibility and fresh-build comparison results are recorded in the milestone report. Native compile file paths are normalized with `-ffile-prefix-map`; the bundle is linked with its install-relative RPATH. Development native-assets JSON containing absolute build paths is excluded from the installed bundle. Flutter’s generated Dart plugin registrant still uses a file URI derived from its extraction prefix in this pinned SDK; the fresh-build binary comparison is reported explicitly. Do not infer cross-prefix or cross-machine bit-for-bit binaries from a successful locked source rebuild or deterministic archives.

The workflow is dispatch-only and requires an owner-approved source-bundle HTTPS URL and SHA-256. It verifies the hash, safely extracts exactly these four siblings and runs the same verifier/package command. No root/donor checkout is needed, and no workflow, package, release or registration was published. For eventual independent repository releases, distribute the four-version source bundle with relative sibling dependencies; for public package publication replace the package-to-package path dependencies with the same locked hosted versions as described in package READMEs. No publication has occurred.

Command evidence is validation/commands/results.json and linked logs. A failed verification gate is not converted into a pass by successfully producing a build artifact. All unavailable display, socket, live-provider, keyring and online-audit gates are separated in milestone-1-report.md.

The final extracted-release check caught CMake’s default directory install removing Java execute bits. The helper directory now uses source permissions and installs its distribution manifest; tar packaging normalizes public file modes while retaining execution. The corrected extracted helper version/framing and distribution checks are recorded in validation/release-content-checks.json.
